# ResearchWiki 0.4 架构

## 分层

- 原件层：内容哈希身份、不可变副本、原页文本和解析器拥有的坐标。
- 抽取层：离线 basic；显式 standard/high/focus 的完整分块执行器；有界 JSON 重试、拆分与原子断点。
- 证据层：独立 Claim 验证和人工审核。quote_matched 只表示引句存在，不表示解释获支持。
- 知识层：统一编译 Paper/Topic/Method/Dataset 专属模板；书目、待核验解读、受支持事实分区，保护个人笔记。
- 检索层：完整原文片段独立索引；Wiki 增量索引及 RRF；问答使用有类型的证据对象和同一预算。
- 交互层：资料库、知识 Wiki、知识图谱、研究问答、设置；高级编译与审核，不包含专用评估。

## 核心不变量

- basic、compile、build 不调用模型。四类 Wiki 由统一编译器生成，不各自发起模型请求。
- 长文不靠首尾截取假装完成；分块规划覆盖全部正文。局部补充更新允许字段，无法可靠选章节时处理全文。
- 不保存残缺 JSON 为成功；断点必须匹配来源/解析器/语言/范围/提示/模型。缓存命中不计入本轮收费请求量。
- 最终完整抽取才发布。深读失败保留已有基础资料、缓存和知识层，任务仍记录失败。
- 只有 supported 论断进入事实知识区；待核验说明不能通过全文索引或用户笔记绕过此门槛。
- 原文可以直接用于问答，但证据卡标明它未经历 Claim 审核，模型解释不会自动晋升。
- 同一个 PDF 的多个片段是不同证据对象，不能仅按 source_id 合并编号。
- 文本匹配只证明原文包含文字，不证明作者结论真实或模型概括正确。
- 私有密钥、原件和运行缓存不进入代码提交；本机工作台不能直接暴露公网。

## 发布与恢复

单线程持久队列领取任务，记录 operation/focus/mode/fresh、进度和耗时。失败重试恢复有效成功块；fresh 使旧审批失效。局部补充只在原来源、版本及陈述/证据/属性完全匹配时保留无关审核。

编译输出与来源版本绑定；原件被修改或生成区与人工内容冲突时阻止覆盖。删除为工作区范围的可恢复操作，保留共享页面和笔记；重新抽取需要显式发起。

## 默认运行条件

Python >=3.9，FastAPI、SQLite/FTS5、PyMuPDF，默认 basic、简体中文解释和本机监听。完整深读默认 12,000 字符块、最多一次额外 JSON 重试、最小拆分子块 2,000 字符、最大拆分深度 2。向量、GROBID 和联网 G6 均非必要依赖。

全流程与接口见 [数据流](data-flow.md)。测试只使用临时数据和模拟提供方；真实提供方连接、费用与吞吐率需另行明确验证。
